# Локальная модель

Локальный сервер отдаёт собранное приложение и обращается только к Ollama по адресу `http://127.0.0.1:11434`. Облачные ключи для этого режима не нужны. Используйте установленную локальную модель, а не облачную модель Ollama.

## Запуск

1. Установите Ollama самостоятельно из официального источника, если она нужна. Этот проект не устанавливает Ollama, не скачивает модели и не запускает модельный сервис.
2. Отключите облачные функции **в процессе самой Ollama**: запустите `OLLAMA_NO_CLOUD=1 ollama serve` (macOS/Linux, после остановки прежнего процесса) или установите переменную среды `OLLAMA_NO_CLOUD=1` для сервиса/приложения Ollama и перезапустите его. Альтернатива: `"disable_ollama_cloud": true` в `~/.ollama/server.json` с последующим перезапуском. В журнале Ollama должна появиться строка `Ollama cloud disabled: true`. Переменная в процессе Node.js не меняет настройки уже работающей Ollama.
3. Заранее установите подходящую для вашего компьютера локальную GGUF-модель. Модель должна отображаться в списке установленных моделей Ollama.
4. Выполните `npm run local`. Скрипт собирает локальный интерфейс и запускает сервер.
5. Откройте `http://127.0.0.1:4174/assistant`. Переход с корневого адреса ведёт на эту страницу.

Для уже собранного приложения сервер запускается напрямую: `node server/local-assistant.mjs`. Он обслуживает каталог `dist`. Остановить сервер можно сочетанием Ctrl+C.

Если Ollama не запущена или в ней нет моделей, интерфейс может показать недоступность или пустой список. Сервер ничего не устанавливает автоматически. Генерация на CPU может быть медленной; ожидание ограничено 90 секундами. Выбирайте модель с учётом памяти компьютера.

## Контракт API

- `GET /local/health`: `{ "available": true, "models": ["qwen3:8b"] }`. При недоступности сервиса: `{ "available": false, "models": [], "error": "…" }`.
- `POST /local/generate`: JSON `{ "model": "qwen3:8b", "prompt": "…" }`, ответ `{ "text": "…" }`. Ошибки возвращают `{ "error": "…" }` и соответствующий HTTP-статус.
- Запрос генерации должен исходить с той же локальной страницы, иметь заголовок `Origin` с её адресом и `Content-Type: application/json`.
- Максимум 32 000 символов в запросе, 64 КиБ в HTTP-теле и 100 000 символов в ответе. Пустые запросы и недопустимые имена моделей отклоняются.
- Параметры генерации фиксированы: `stream: false`, `temperature: 0.7`, `num_predict: 1200`. Инструменты модели не передаются.

## Проверка локальности модели

Сам адрес `127.0.0.1` не гарантирует локальное выполнение: Ollama умеет пересылать запросы облачным моделям. Поэтому отключение облака в Ollama обязательно. Сервер не может проверить переменные среды другого процесса и не меняет их автоматически.

Список моделей скрывает известные облачные имена (`:cloud`, `-cloud`) и записи с `remote_model`/`remote_host`. Перед каждой генерацией сервер запрашивает `/api/show`, передавая только имя модели, без пользовательского запроса. Генерация разрешена, только если описание содержит формат `gguf`, архитектуру локальной модели и не содержит признаков облачного/удалённого подключения. Неизвестное, отсутствующее или ошибочное описание блокирует генерацию. Дополнительная проверка может отклонить некоторые локальные форматы: автоматически обходить её нельзя.

Эти проверки дополняют, но не заменяют отключение облака в Ollama. Они не доказывают безопасность изменённого локального сервиса или одновременной подмены модели другим процессом. Для более строгой изоляции запускайте Ollama без сетевого доступа после получения модели.

Официальные источники: [отключение облака Ollama](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features), [описание `/api/show`](https://docs.ollama.com/api-reference/show-model-details).

## Ограничения безопасности

Сервер привязан только к `127.0.0.1:4174`, не открывает CORS и отклоняет посторонние Host/Origin. Адрес Ollama жёстко задан: удалённый прокси настроить нельзя, HTTP-переадресации не выполняются. Не публикуйте сервер через туннель или обратный прокси. Защита локального компьютера и настройки самой Ollama остаются ответственностью владельца.

Тексты запросов и ответов не журналируются сервером. После проверки модели они передаются в локальный процесс Ollama. Выполнение без облачной пересылки требует описанной выше настройки самой Ollama. Сам сервер не читает аккаунты, почту, Threads или другие пользовательские источники, не публикует контент и не отправляет сообщения. Эта гарантия относится к данному серверу и локальной генерации, а не ко всем другим функциям приложения или настройкам стороннего сервиса Ollama.

## Проверка

`node --test tests/local-server.test.mjs`

Тесты используют подменённый `fetch`, временные файлы и порт loopback. Проверяются доступность модели, генерация и ошибки, ограничения размера, таймаут, Host/Origin, MIME, SPA-маршруты, обход пути и запрет внешней привязки. Дополнительно проверяется, что облачные имена, удалённые метаданные и неудачная проверка `/api/show` не приводят к вызову `/api/generate`. Реальная Ollama и сторонние сервисы не вызываются.
