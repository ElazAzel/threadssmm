# Threads без обязательных ключей: исследование решений

Дата исследования: 9 ноября 2026. Краткое восстановленное резюме проверенных находок; сторонний код не копировался и не запускался.

## Поддерживаемый путь без API-ключей

[Официальные Threads Web Intents](https://developers.facebook.com/documentation/threads/threads-web-intents) открывают редактор `https://www.threads.com/intent/post` с параметрами `text`, `url`, `tag`, `reply_control`, `reply_post_shortcode` и `quote_post_shortcode`. Параметры необходимо URL-encode. Пользователь входит в Threads и сам завершает отправку. Это не фоновая публикация и не подтверждение факта отправки.

Поэтому работоспособный keyless-фундамент: пользовательский импорт или явный сбор видимых постов, локальный анализ и хранение, шаблоны/локальная модель, проверка человеком, Web Intent для конкретного поста или ответа. Текст шаблона нельзя выдавать за результат AI, а оценку импортированной выборки — за глобальный тренд.

## Что даёт официальный API и чего он требует

- [Get started](https://developers.facebook.com/documentation/threads/get-started): OAuth-токен, Threads App ID и secret; tester-аккаунты для разработки, App Review и опубликованное приложение для более широкого доступа.
- [Keyword search](https://developers.facebook.com/documentation/threads/keyword-search): поиск зависит от разрешения `threads_keyword_search`. Без одобрения область ограничена собственными публикациями; это не свободный поиск всего Threads без авторизации.
- [Insights](https://developers.facebook.com/documentation/threads/insights): официальные метрики собственных публикаций. Нельзя обещать полные insights чужих аккаунтов по публичной ленте.
- [Profile discovery](https://developers.facebook.com/documentation/threads/threads-profiles): отдельные разрешения и ограничения доступа/публичных профилей. Открытый интерфейс профиля не равнозначен неограниченному API.

Лимиты и условия Meta меняются; перед реализацией автоматического режима нужно перечитать текущую документацию выбранных scopes. API остаётся отдельной опцией для поддерживаемой синхронизации и публикации по расписанию.

## Проверенные ловушки открытых реализаций

- [junhoyeo/threads-api](https://github.com/junhoyeo/threads-api): архивирован, разработка прекращена после сообщения Meta в сентябре 2023. Связанный threads-py имеет ту же проблему. Не использовать как поддерживаемое ядро нового продукта.
- [logiover/threads-scraper](https://github.com/logiover/threads-scraper): обещание «no API key» не означает автономный открытый движок; репозиторий описывает внешний Apify Actor. Это сохраняет внешнюю сервисную зависимость.
- [nerin81-netizen/threads-affiliate-automation](https://github.com/nerin81-netizen/threads-affiliate-automation): свежие обновления сами по себе не доказывают пригодность; исследованный package.json зависел от прекращённого `threads-api ^1.6.3`, AI — от Gemini key.
- [itsmaxyd/threads-downloader](https://github.com/itsmaxyd/threads-downloader): README упоминал MIT, но фактический LICENSE и metadata указывали GPL-3.0. Нельзя переносить код, полагаясь только на README.

Неофициальные клиенты с приватными GraphQL document IDs, извлечёнными cookies и reverse-engineered endpoints имеют существенный риск поломок и ограничений аккаунта. Они не делают обещание «полностью работает без API» надёжным.

## Архитектурное решение

1. Настоящий локальный режим отделён от demo и облачной авторизации.
2. Сборщик запускается только явным действием на видимой вкладке, без cookies, паролей, скрытого обхода или фонового сканирования.
3. Неведомые метрики сохраняются как неизвестные. Источник и метод расчёта доступны для проверки.
4. Локальная модель необязательна; её облачные возможности отключаются и проверяются отдельно. См. [инструкцию Ollama](local-model.md).
5. Черновик, проверенный текст и пользовательское подтверждение публикации — разные состояния. Открытие intent не устанавливает статус «опубликован».
6. Полная автономность требует отдельной реальной приёмки, согласованных источников/профиля и правил отправки. См. [roadmap](autonomy-roadmap.md).
